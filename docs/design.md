# DuckDB独立拡張fileindex：CSV・固定長ファイルへの永続索引

## 決定

`DuckDB-FileIndex`を独立したDuckDB拡張として提供する。
利用者は公式DuckDBと拡張ファイルだけで、元ファイルへの永続索引を作り、SQLから検索できる。
常駐サーバー、Rustクレート、ODBC、Pythonを実行時の前提にしない。
制約と実行例は[マニュアル](../README.md)に記載する。

## 公開APIと実装境界

- `file_index_create(source,index,...)`：キー型・キー列・ファイル形式を指定して永続索引を作る。
- `file_index_scan(index)`：索引のスキーマでファイルを読み、SQLの条件を受け取る。
- 使い勝手は`CREATE VIEW name AS SELECT * FROM file_index_scan(...)`で通常のテーブルに近づける。
- DuckDB TableFunctionのprojection/filter pushdownを利用する。標準の`read_csv`やDuckDB本体は改変しない。
- 外部ファイルの位置を引く索引と読取処理を拡張が持ち、結合・集約・ウィンドウ処理はDuckDBが持つ。
- APIはDuckDBのテーブル関数とし、SQLの構文・結合・集約等はDuckDBに任せる。

## 対応範囲

CSVのRFC 4180形式の引用符と引用符内改行、CRLF/LF、UTF-8 BOMを扱う。
固定長はレコード長と列幅をバイト数で指定し、端数レコードを拒否する。
両形式ともUTF-8。索引キーは最大32列のBIGINTまたはVARCHARで、重複とNULLを保持する。
キー以外の型変換は利用者のSQLで行う。

キー値と元ファイルの位置・長さをソートし、索引本体と、可変長エントリーを引く位置ディレクトリを保存する。
元ファイル全体をDuckDBへ恒久的にコピーすることはしない。
構築時の一時的なキーソートには内部DuckDBを利用して、メモリ予算とソート一時領域の上限を設定する。
完成索引の全エントリーを検索時にメモリへ展開せず、ディスク上で二分探索する。

SQLの等価・範囲条件とANDの組み合わせを二分探索へ変換する。
選択範囲が広いときは逐次走査し、CAST・関数・照合順序等を含む残余式はDuckDBに評価させる。
EXPLAIN ANALYZEに選択した方式と取得データレコード数を表示して、単にWHEREの結果が合うだけでなく
必要なデータレコードだけを取得できたことを検証する。
現在はヒストグラムに基づく費用モデルではなく、候補件数による明示的な閾値を使う。

## 変更検知と公開

サイズ・更新時刻で通常の変更を検知し、`verify := true`では元ファイル全体のFNV-1aも照合する。
強い検査は全ファイルの読み取りが必要なため、通常の検索とはI/O特性が異なることを明記する。
処理中の元ファイルは不変を前提とし、ファイル更新をDBのトランザクションで保護できるとは説明しない。
再作成は旧索引を保ちながら専用一時領域へ構築し、完成後にだけ公開する。
データファイルを変更するAPIは設けず、通常エラーで旧索引や元ファイルを消さない。
索引に含まれるキー・フルパスの管理、空きディスク、強制終了時の残骸の扱いはヘルプへ記載する。

## ビルド・互換性・CI

現在はDuckDB v1.4.1に固定し、公式SDK・CLIと同じC++ APIで構築する。
SDKの取得物にはSHA256を固定する。更新時はバージョン・メタデータ・両OSの試験をまとめて更新する。
Windows x64/MSVC 2022とLinux x64/C++17を独立CIで検証する。
両OSともDuckDBを静的リンクし、拡張のAPIを通じてホストへ登録する。DuckDB CLIと拡張ファイルだけを
隔離したディレクトリへ置く試験で、追加のduckdb.dll/libduckdb.soが不要であることを確認する。
拡張の署名・Community Extensionsへの登録は別工程で、現在は未署名拡張として配布する。

試験は実際のDuckDB CLIへLOADし、別プロセスで索引を再利用する。
RFC CSV、日本語、重複・NULL・整数限界、非先頭キー、残余条件、照合順序、集約・結合・ウィンドウ、
空ファイル、不正データ、元ファイル更新、破損・切れた索引、再構築失敗時の保全を含める。
性能はCLI起動込みの時間とレコード取得数を分けて報告し、ウォームキャッシュの結果を物理I/O削減と混同しない。

## 後続改善

DECIMAL/日付キー、EBCDIC/COMP-3、差分索引更新、OR/INの複数範囲検索、
索引のヒストグラム・サンプリング、並列スキャン、全体チェックサム、オンライン更新を別段階で検討する。
これらを対応済みとして表示しない。
ビルド・CI・配布を独立させ、DuckDBと拡張だけで実行できるようにする。

## 複合索引

`key_columns`と`key_types`で最大32列の複合索引を指定する。型は列ごとにVARCHAR/BIGINTを選ぶ。
先頭から連続する等価条件と、次の列の範囲条件で辞書順索引を二分探索する。
先頭列を使わない条件や広い候補範囲は逐次走査し、すべての条件の意味を維持する。
単一列索引はv1形式、複合索引はv2形式で保存する。両形式を読み取る。
混合型・NULL・重複・範囲・非先頭キー・固定長・v1/v2形式の読み取り・最大列数を実DuckDBで検証する。
